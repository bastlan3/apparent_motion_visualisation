Methods (Farrell & Shepard, 1981, JEP:HPP 7(2), 477–486)
Observers: 8; 3 sessions × 60 recorded trials = 180 recorded trials each, after practice trials and a few warm-up trials per session (p. 479–480).
Stimulus: one polygon at a time, centred. Each of 3 random polygons (A, B, C) has one vertex on each of 18 equally spaced radii (20° apart); two vertices 8 units from the origin in opposite directions define the vertical axis; the other 16 radii are drawn from 1–17 excluding 8, without replacement; adjacent vertices joined by straight lines (p. 479). Symmetric versions: cut along the vertical axis and join the half to a copy rotated 180° (left-side / right-side versions). Intermediate polygons interpolate along each radius ¼, ½, ¾ of the way from asymmetric to symmetric: 0, 25, 50, 75, 100% (27 distinct polygons; each observer saw 15, with left- or right-side versions counterbalanced). Size: ≈ 4.8° visual angle at a “standard viewing distance” (p. 480).
Sequence: alternation between the “upright” orientation (defined by the vertical axis) and an orientation displaced by 30, 60, 90, 120, 150 or 180° clockwise or counterclockwise (fixed within a trial); each view immediately replaces the other, no ISI, so SOA = duration of each view. SOA starts at 1 s on every trial (p. 480).
Response: left/right keys of a response panel change each field's duration by 10% (speed up / slow down; assignment counterbalanced), centre key records SOA₁ then SOA₂, which ends the trial. If rigid rotation could not be seen, observers noted this on a comment sheet. Design: random order, 1 trial per polygon (15) × 12 disparities (6 clockwise + 6 counterclockwise, 180° counted in both directions) = 180 (p. 480). Page: observer number fixes the left/right-side version set and key assignment (counterbalanced over observers in the paper); a session runner serves the shuffled 180 trials as 3 × 60 after a few warm-up trials. Practice trials are not implemented (number unspecified).
Page timing: refresh rate is measured at load (median of ~60 rAF intervals); every duration is converted to a whole number of frames at that rate and scheduled by counting frames. A nominal SOA (ms) starts at 1000 and is multiplied by exactly 0.9 or 1.1 per tap (1000 × 0.9^k or 1.1^k); the displayed SOA is round(nominal / frame) frames (at least 1), so the 10% step law is not distorted by frame rounding. The CSV logs nominal ms, realised frames and realised ms. The display line under the canvas shows the realised durations and warns if 1 s is not a whole number of frames.
Display setup: screen px/cm (credit-card calibration, default 37.8) and viewing distance (default 57 cm, assumption: the paper says only “standard viewing distance”) give px/degree; the polygon is drawn at 4.8° (p. 480). Stored in localStorage key “am_display”.
Assumptions (not specified in paper): the nominal SOA is not allowed to fall below one display frame (floor is an assumption); exact radii of A, B, C are shown only in the paper's Fig. 1, so the radii of A, B and C were digitised from the top row of Fig. 1 (ray-casting from the origin midway between the two 8-unit axis points; scale from the 8-unit axis points; accuracy about ±1 unit), then snapped by rank order to a permutation of {1..17} excluding 8, as the paper's recipe requires. Digitising error remains. The polygon is drawn at a size that follows px/degree; the canvas is resized to fit it (a warning shows if the window is too small). Speed-up multiplies SOA by 0.9; slow-down by 1.1 (paper says “the same 10% steps”). Minimum SOA 1 frame; no upper cap. Rendered as a green (P31 phosphor) outline, 2 px line, black background, no fill, no fixation point; luminance, line width, viewing distance, refresh rate unspecified. 4.8° taken as the diameter of the circle containing radius 17 (assumption). Which view is shown first is unspecified (upright first here). Apparatus: Tektronix 604 CRT, P31 phosphor, dimly lit room.
